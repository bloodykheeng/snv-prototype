# P4FP Uganda MEL Platform: prototype and mockups

Presentation-stage prototype made by New Wave Technologies for SNV's **P4FP Uganda MEL Platform** tender (September 2026).

- **Live prototype:** https://snv-prototype.vercel.app (Vercel redeploys on every push to `main`)
- **Team briefing** (internal, not for SNV): [`BRIEFING.md`](BRIEFING.md) · web version at `/briefing.html`
- **36 screens:** 23 web (1920×1080) and 13 screens of the Android field app (360×800, built in Flutter)
- All names, figures and outcomes are **illustrative**. The district boundaries are real.

This README is for anyone, human or AI, who needs to change or extend the prototype.

---

## 1. How it was made (the idea in one paragraph)

Nothing here is drawn by hand. Every screen is **generated by Python** (`_src/`) as a plain **SVG** made of rectangles, paths, circles and live text. Plain SVG does two jobs: browsers show it, and **Adobe XD imports it as editable layers**. The same Python also records **hotspots** (clickable rectangles and the screen each one opens). `build.py` then writes `prototype.html`, a single self-contained page that shows one SVG at a time and puts invisible click areas over it. That page is what people click through.

```
_src/*.py  ──python build.py──►  web/*.svg + mobile/*.svg   (the screens)
                             └►  prototype.html              (viewer + all hotspots, embedded as JSON)
_src/combine.py ─────────────►  all-screens.svg             (every screen in one file, for a single XD import)
```

## 3. The drawing kit (`_src/kit.py`)

**`SVG` class.** Each screen is `s = SVG(width, height, title)`. Drawing calls add elements: `s.rect`, `s.circle`, `s.line`, `s.path`, `s.poly`, `s.text`, `s.para` (wrapped text) and `s.icon`. `with s.g("name"):` groups elements; group and element `id`s become **XD layer names**, and duplicate ids are numbered automatically.

**Text is measured, not guessed.** `tw(text, size, weight)` measures width with the real **Segoe UI** font files (`C:/Windows/Fonts/segoeui*.ttf`, via Pillow). Every `<text>` is written left-anchored at a computed x, so right-aligned and centred text lands correctly even in importers that ignore `text-anchor`. `maxw=` truncates with an ellipsis; `wrap()`/`para()` wrap lines.

**Icons** are Lucide-style stroke paths on a 24px grid, kept in the `ICONS` dict. `s.icon(name, x, y, size, colour)`.

**Components:** `chip`, `status_chip`, `button` (primary / secondary / soft / ghost / danger), `card`, `progress`, `avatar`, `checkbox`, `radio`, `toggle`, `field` (label + input), `table` (cells can be strings or drawing functions), `logo_mark`.

**Palette and fixed vocabularies** sit at the top of `kit.py`: `STATUS` colours (Approved, Returned, Under review…), `PATHWAY` colours (LEARN/LINK/LEVERAGE), `REGION` colours, `SIGNALS` (SS1–SS8, **placeholder names**), `PARTNERS` (the 8 real partners). Change them there and every screen follows.

**Hotspots:** `s.link(x, y, w, h, "w05")` records a clickable area that opens screen `w05`. Nothing is drawn; it only goes into the prototype's data.

## 4. Charts and the map (`_src/charts.py`)

- `radar()` draws the SS1–SS8 spiderweb with several series (filled = current, dashed = earlier).
- `donut()`, `line_chart()` and `arc_path()` are plain paths.
- `UgandaMap(x, y, w, h)` projects the GeoJSON onto the given box (simple lon/lat scaling), simplifies each district with Ramer–Douglas–Peucker, and offers `draw_base`, `draw_programme` (colour by region or adoption), `labels`, `centroid`, `random_points` (fake GPS points inside a district, seeded so they don't change between builds) and `d(name)` (the path for one district).
- `P4FP_DISTRICTS`, `ADOPTION` and `PARTNER_AREAS` hold the 15 programme districts, the illustrative adoption counts, and which partner works where.

The district rings are closed (first point = last point), so each ring is split in half before simplifying. Without that split the simplifier collapses every district to a single point.

## 5. Screens, keys and the build

**Every screen is a function** that returns an `SVG`. The function name sets its **key**: the part before the first underscore (`w05_report_review` → `w05`, `w10b_partner_indicators` → `w10b`, `m07_adoption` → `m07`). Hotspots and URLs use these keys (`prototype.html#w05`).

**Registration:** each module has a `SCREENS` list (`mobile2` has `FIRST` and `LAST`). `build.py` gathers them. Web screens are sorted by key number (so `w09p` sits after `w09`); mobile screens run in list order. That order is what ← → steps through.

**Shells:**
- `web.shell(title, active, crumbs, user, nav)` draws the sidebar, top bar, period selector, search, bell, user card and the **sign-out** button. `NAV_SNV` and `NAV_PARTNER` define the menus; `NAV_TARGET` and `NAV_TARGET_PARTNER` map each menu label to a screen key.
- **Partner mode:** `web.PARTNER_MODE["on"] = True` makes any shared screen render inside Brian's NREP shell. `web4._as_partner()` uses it to make `w09p` and `w12p`, so a partner never lands in the SNV view.
- `mobile.phone()`, `app_bar()` and `bottom_nav()` do the same for the app. The bottom tabs link Home `m06`, Capture `m07`, Outcomes `m09`, Sync `m10`, Me `m13`.

**Commands:**
```
cd _src
python build.py              # rebuild every screen + prototype.html
python build.py --png        # also render PNGs into _previews/ (uses Chrome, see section 8)
python build.py w02 m07      # rebuild only screens whose function name contains these strings
                             # (partial builds do NOT rewrite prototype.html)
python combine.py            # rewrite all-screens.svg after a rebuild
```

**Renaming a screen changes its file name.** Delete the old SVG from `web/` or `mobile/`, otherwise it lingers (and shows up in `all-screens.svg`).

## 6. How the clickable prototype works (`PROTO` in `build.py`)

`build.py` writes one JSON array into `prototype.html`: for each screen its `key`, `title`, `src`, size, whether it's mobile, and its `links` (hotspot rectangles in SVG coordinates). The page then:

- **Shows one screen** as an `<img>` of the SVG, scaled to fit the window (`fit()`).
- **Places hotspots** as absolutely positioned `<div>`s using percentages of the screen size, so they stay aligned at any zoom. Clicking one calls `go(target)`.
- **Routes by URL hash:** `#w05` opens screen `w05`. With no hash it opens `w00` (landing page), or `m01` (splash) on phones.
- **Flashes hotspots** when you click empty space, like XD; **H** keeps them visible; `?show` in the URL turns them on (handy for checking alignment).
- **Keyboard:** ← → previous/next · **F** full screen · **Esc** exits full screen · **H** hotspots.
- **Auto-advance:** the `AUTO` object (`{ m01: ['m02', 1800] }`) moves the splash to Welcome after 1.8 s.
- **Offline-ready:** on load it downloads every SVG into memory (`CACHE`). The toolbar shows "Loading n/36…", then "✓ Offline-ready". After that, switching screens needs no network. If a screen fails to load, a message says so instead of leaving the old screen showing.
- **Full screen:** uses the Fullscreen API. In full screen the toolbar hides and slides back when the mouse nears the bottom edge.

**Responsive rules:**
- Toolbar items never wrap. Below 1500px the keyboard hint hides.
- **≤ 760px (phones):** compact toolbar (pill, status and long labels hidden, select stretches); app screens fill the screen with no phone frame; web screens fit the width, and a "Turn your phone sideways" hint shows in portrait.
- Web screens are designed for a laptop or projector; on a phone they are readable only in landscape or when zoomed.

**Share previews:** `index.html` and `prototype.html` carry the description, favicon links and Open Graph/Twitter tags pointing at `https://snv-prototype.vercel.app/og-image.jpg`. The tag block lives in the `PROTO` template and in `index.html`. WhatsApp caches previews per URL; to force a fresh one, share with a query string (`/?v=3`).

## 7. Adding or changing a screen (checklist)

1. Write a function in the right module, named `wNN_something` or `mNN_something`. Start from a similar screen: web screens call `shell(...)` and use `X0`/`X1`/`CW`/`Y0`/`H` for layout; mobile screens call `phone(...)`.
2. Add it to that module's `SCREENS` list.
3. Add `s.link(...)` hotspots out of it, and add links **into** it from other screens (menu entries go in `NAV_TARGET` / `NAV_TARGET_PARTNER`).
4. `python build.py && python combine.py`, then check it: `python build.py --png <name>`, or open `prototype.html?show#<key>` to see the hotspots.
5. Commit and push; Vercel redeploys.

**Rules to keep the prototype consistent:**
- **Roles** (use exactly these names): Super Admin · SNV MEL Reviewer (Grace Akello, SNV) · Partner MEL Focal Person (Brian Tumusiime, NREP) · Partner Field User (Sarah Nakato, NOGAMU) · Read-only. The ToR's minimum roles are Super Administrator, Partner MEL Focal Person, Partner Field/Data Entry User and Read-Only User; "SNV MEL Reviewer" comes from the NWT proposal.
- **A partner user must never land on an SNV-only screen.** Partner menus and links go only to partner screens or partner-mode versions.
- **The mobile app is a Flutter Android app** (not a PWA).
- **Only approved data counts** in dashboards, exports and LogAlto; screens should keep showing that rule.
- **SS1–SS8 names are placeholders**; only SS5 = adoption / PHI 8 comes from the ToR.

## 8. Environment assumptions

- **Windows.** Fonts are read from `C:/Windows/Fonts` (Segoe UI) in `kit.py`. On another OS, point `FONT_FILES` at Segoe UI or a close substitute (layout will shift slightly).
- **Python 3 + Pillow** (`pip install pillow`). No other dependencies.
- **PNG previews** use headless Chrome at `C:\Program Files\Google\Chrome\Application\chrome.exe` (`CHROME` in `build.py`). Headless Chrome won't render narrower than about 500px, so phone-width screenshots look cut off even when the real page is fine.
- **Vercel:** framework preset "Other", no build command, output = repo root. The generated files are committed, so Vercel serves them as they are and never runs Python.

## 9. Using the screens in Adobe XD

- **All at once:** File → Import (Ctrl+Shift+I) → `all-screens.svg` → Ungroup once (Ctrl+Shift+G). Each screen becomes a named group.
- **One at a time:** import any file from `web/` or `mobile/`.
- Imported SVGs land as groups, not artboards. To prototype inside XD, draw an artboard (**A**, Web 1920 or custom 360×800) over a screen.
- Edits made in XD are lost if the screen is regenerated; for lasting changes, edit the Python.
